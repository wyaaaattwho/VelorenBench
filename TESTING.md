## Wheel and sdist installation away from the checkout

Build as in BUILD.md. The verification helper creates a new venv/HOME,
installs an artifact, proves imports come from it and the core initially
has no SDK/runtime dependencies, runs CLI/help commands, then installs
test dependencies and copies only source tests/tools into an isolated work
directory. It logs commands and receipts **outside** the publishable tree.

```sh
python3 tools/verify_install.py --artifact /absolute/python-dist/FILE.whl \
  --root /absolute/new-wheel-check \
  --tests test_candidate054.py test_portability.py test_public_source.py
python3 tools/verify_install.py --artifact /absolute/python-dist/FILE.tar.gz \
  --root /absolute/new-sdist-check --sdk
```

Use `--sdk` for the full original test collection. For offline installation,
pass `--wheelhouse DIR` containing all hash-locked required build/test wheels;
otherwise pip uses its configured public index. No internal wheelhouse is
required. Native source/tools identity is verified separately from the Git
checkout using `python3 -B tools/package_source.py --check` and
`build_native.py --check` with external assets. These checks do not compile
Rust, validate a GPU or create gameplay/model results.

## Renderer startup and applied aim

`test_renderer_startup.py` exercises newline-framed Xserver `-displayfd`
readiness, including split digit/newline writes, malformed or truncated output,
and reader cancellation. The pipe must stay open until the complete line is
consumed: Xserver may otherwise terminate on its final newline write even when
the display digits were already received. The existing startup operation
deadlines and post-publication `xdpyinfo` responsiveness check are unchanged.

The native client test `applied_look_uses_controller_pitch_and_body_heading`
uses the production `look_at`/`turn` completion predicate. Ordinary ranged aim
combines the applied controller pitch with body heading, as the game's ranged
action does; upright body orientation alone is not a 3-D aim direction. The
test retains the existing alignment tolerance and rejects unapplied input or
incorrect heading. Installed native checks must also exercise pitched aim and
actual projectile contact, not just a passing mathematical predicate.

These changes do not alter task definitions, setup placements, NPC behavior,
scorers, difficulty or qualification policy. A setup timeout or returning
ambient creature remains a real, retained failed opening, not an Agent failure
or proof of a different shared defect. Prior deployment evidence must retain
its original identities; successor qualification keys are generated afresh.

`test_navigation_profile_contract.py` checks that the original supply-free N2
rendezvous, including an arbitrary-ID extension of its shared template, does
not require a pickup interface. The historical `supply_rendezvous` template
name stays compatible. Image `visual-motor-v1` can therefore open this
arrival-only task; the profile itself gains no pickup/UI/map operations, and
other feature restrictions and qualification admission remain unchanged.
Original scene bytes, layout, goal text, setup and scorer are not modified.

The same regressions check the inverse contract: original N5's `natural_long`
layout requires actual apple pickup/retention and uses `pickup_rendezvous`.
Both image profiles are checked against the complete public tool schema,
including step variants and held controls, not just feature names.
`visual-motor-v1` is refused for the pickup layout; `visual-ui-v1` keeps its
fenced HUD interaction route. Arbitrary-ID author manifests and explicit
incompatible templates cannot omit that dependency, nor can the pickup template
invent a supply requirement for supply-free layouts. Generated TASKS/SUPPORT
sections include the pickup requirement and the legacy-profile refusal.
Installed checks must preserve the original full-UI goal, authored apple,
original false/no-goal outcome and normal cleanup; an opening or dispatch is
not pickup evidence or a task victory.

## Shared nearest-pickup attribution

`test_pickup_attribution.py` covers omitted and explicit request UIDs through
the shared native receipt predicate. It rejects wrong actor/session/action or
target/item/amount, explicit mismatched/null UID, incomplete status, absent or
non-Collected server feedback, unjustified and ambiguous candidates, and
inventory/disappearance-only proxies. Image HUD canonicalization retains its
exact original-request provenance fence and uses the same attribution.

Consumer regressions cover target availability, navigation interaction,
pickup-dependent crafting/recovery, and the authored route event's one-time
trigger and original scorer. A confirmed collection does not grant arrival,
craft completion, retention or public visibility. Installed native validation
must additionally exercise public `game_step` pickup with UID omitted, collect
the original native receipt, and join the authored event/scorer to a later
ordinary public terrain readback. Unit fixtures alone do not establish that
effect, and an explicit-UID run does not cover the omitted-UID branch.
